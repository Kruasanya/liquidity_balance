# Прогнозирование сальдо ликвидность 

Проект реализует автоматизированный пайплайн прогнозирования `Balance` по истории притоков (`Income`), оттоков (`Outcome`), сальдо (`Balance`) и внешним макро/рыночным факторам.

Основная точка входа для регулярного запуска: `main.ipynb`.

Исследовательские ноутбуки `time_series.ipynb`, `time_series_executed_check.ipynb` и `time_series_outlier_check.ipynb` оставлены как материалы анализа. Эксплуатационный пайплайн вынесен в отдельные Python-модули в папке `balance_pipeline`.

## Что реализовано

Пайплайн делает полный цикл работы по требованиям из `PIPELINE_SPEC.md`:

- загружает основной файл `Project 1_2024.xlsx`, лист `Data`;
- загружает внешние факторы:
  - ключевая ставка, инфляция, цель по инфляции;
  - RUONIA и объем сделок RUONIA;
  - USD/RUB;
- проверяет качество данных:
  - обязательные колонки;
  - корректность дат;
  - дубликаты дат;
  - пропуски;
  - сортировку;
  - непрерывность календарного ряда;
  - расхождение `Balance` и `Income - Outcome`;
- строит признаки:
  - календарные признаки;
  - налоговые признаки вокруг 28-го числа;
  - лаги `Balance`, `Income`, `Outcome`;
  - rolling mean/std;
  - макро/рыночные признаки;
  - outlier-флаги;
- сравнивает модели на walk-forward проверке:
  - `zero`;
  - `last_value`;
  - `seasonal_naive_5`;
  - `rolling_mean_5`;
  - `rolling_mean_10`;
  - `rolling_mean_20`;
  - `day_of_week_mean`;
  - `Lasso`;
  - `ExtraTreesRegressor`;
- считает метрики:
  - `business_loss`;
  - `MAE`;
  - `RMSE`;
  - `share_abs_error_le_0_42`;
  - `bias_mean_error`;
- выбирает финальную модель по многокритериальному правилу;
- обучает финальную модель только на истории до `FORECAST_DATE`;
- сохраняет production-чекпоинт;
- строит прогноз на указанную дату;
- если факт за дату уже есть, добавляет `actual_balance`, ошибку и бизнес-метрики;
- пишет лог прогнозов;
- строит drift-отчет и рекомендацию по дообучению.

## Структура проекта


Назначение модулей:

- `balance_pipeline/config.py` — параметры запуска.
- `balance_pipeline/data.py` — загрузка и валидация данных.
- `balance_pipeline/features.py` — построение признаков.
- `balance_pipeline/metrics.py` — бизнес-метрика и технические метрики.
- `balance_pipeline/modeling.py` — walk-forward проверка, выбор кандидатов, обучение и прогноз.
- `balance_pipeline/artifacts.py` — сохранение модели, конфигов и логов.
- `balance_pipeline/monitoring.py` — drift-отчет.
- `balance_pipeline/runner.py` — единая функция запуска `run_pipeline`.
- `balance_pipeline/core.py` — основная реализация функций, которые переиспользуются модулями.
- `pipeline.py` — короткий совместимый импортный слой для запуска `PipelineConfig` и `run_pipeline`.

## Как пользоваться

1. Убедиться, что в папке проекта лежат входные файлы:

```text
Project 1_2024.xlsx
Инфляция и ключевая ставка Банка России_F01_01_2017_T29_05_2026.xlsx
RC_F01_01_2017_T28_05_2026.xlsx
RC_F01_01_2017_T30_05_2026.xlsx
```

2. Открыть `main.ipynb`.

3. В блоке `CONFIG` указать дату прогноза:

```python
forecast_date=None
```

`None` означает прогноз на следующий рабочий день после последней даты в основном файле.

Если нужен прогноз на конкретную дату, указать строку:

```python
forecast_date="2021-03-31"
```

4. Запустить весь ноутбук сверху вниз через `Run All`.

5. Смотреть результат в блоке `Run pipeline`.

Главная колонка итогового прогноза:

```text
predicted_balance
```

В короткой таблице также выводятся:

- `forecast_for_date` — дата прогноза;
- `actual_balance` — факт, если дата уже есть в данных;
- `abs_error` — абсолютная ошибка, если факт есть;
- `abs_error_le_0_42` — попал ли прогноз в требуемый порог ошибки;
- `model_type` — выбранная модель;
- `is_tax_day_28` — налоговый день;
- `is_tax_window_28` — налоговое окно;
- `has_recent_balance_outlier` — недавний outlier-режим;
- `feature_outlier_alert` — флаг необычных значений признаков;
- `comment` — пояснение по прогнозу.

## Как добавить новые данные

Новые данные добавляются через обновление входных Excel-файлов. Отдельно править код пайплайна для этого не нужно.

### 1. Обновить основной файл

Основной файл:

```text
Project 1_2024.xlsx
```

В нем должен быть лист:

```text
Data
```

На листе `Data` должны быть колонки:

```text
Date
Income
Outcome
Balance
```

Чтобы добавить новые фактические дни, нужно дописать новые строки вниз таблицы. Формат остается тем же:

```text
Date        Income      Outcome     Balance
2021-04-01  ...         ...         ...
2021-04-02  ...         ...         ...
```

Важно:

- `Date` должна корректно читаться как дата;
- не должно быть дублей по `Date`;
- `Income`, `Outcome`, `Balance` должны быть числовыми;
- если факт за день еще неизвестен, этот день лучше не добавлять в основной файл как факт;
- если строка с датой уже добавлена, пайплайн считает, что факт за эту дату доступен, и после прогноза рассчитает ошибку.

### 2. Обновить внешние факторы

Если появились свежие макро/рыночные данные, нужно заменить или обновить файлы:

```text
Инфляция и ключевая ставка Банка России_F01_01_2017_T29_05_2026.xlsx
RC_F01_01_2017_T28_05_2026.xlsx
RC_F01_01_2017_T30_05_2026.xlsx
```

Названия файлов сейчас прописаны в `CONFIG` внутри `main.ipynb`.

Если новые файлы называются так же, достаточно заменить старые файлы в папке проекта.

Если новые файлы называются иначе, нужно изменить пути в блоке `CONFIG`:

```python
CONFIG = PipelineConfig(
    main_file="Project 1_2024.xlsx",
    macro_file="новый_файл_со_ставкой_и_инфляцией.xlsx",
    ruonia_file="новый_файл_ruonia.xlsx",
    usd_file="новый_файл_usd_rub.xlsx",
)
```

### 3. Выбрать дату прогноза

В `main.ipynb` в блоке `CONFIG` есть параметр:

```python
forecast_date=None
```

Есть два обычных сценария.

Сценарий 1: прогноз на следующий рабочий день после последнего факта.

```python
forecast_date=None
```

Например, если последний факт в `Project 1_2024.xlsx` — `2021-03-31`, пайплайн построит прогноз на следующий рабочий день.

Сценарий 2: прогноз или проверка качества на конкретную дату.

```python
forecast_date="2021-03-31"
```

Если эта дата уже есть в основном файле, пайплайн:

- построит прогноз так, как будто факт этого дня еще неизвестен;
- затем добавит `actual_balance`;
- посчитает `abs_error`, `business_loss`, `abs_error_le_0_42`.

Если этой даты еще нет в основном файле, пайплайн:

- вернет только прогноз;
- поля `actual_balance`, `abs_error`, `business_loss` оставит пустыми.

### 4. Запустить ноутбук

После обновления файлов нужно открыть `main.ipynb` и запустить `Run All`.

Пайплайн сам:

- загрузит обновленные данные;
- проверит качество;
- построит признаки;
- проверит, подходит ли текущий production-чекпоинт;
- при необходимости обучит новую модель;
- построит прогноз;
- сохранит прогноз в лог.

### 5. Где увидеть результат после добавления данных

Главный результат появляется в блоке:

```text
Run pipeline
```

Итоговое предсказание находится в колонке:

```text
predicted_balance
```

Полная таблица прогноза находится ниже, в блоке:

```text
Forecast for date
```

История всех прогнозов сохраняется здесь:

```text
artifacts/forecasts/forecast_log.csv
```

### 6. Что происходит с моделью после добавления данных

Если новый прогноз строится на дату после последнего обучающего периода, пайплайн проверяет production-чекпоинт в:

```text
artifacts/models/latest/
```

Если чекпоинт подходит, он используется повторно.

Если чекпоинт отсутствует или обучен на неподходящем периоде, пайплайн автоматически обучает новую модель на истории до `FORECAST_DATE` и обновляет:

```text
artifacts/models/latest/
```

Старые версии модели сохраняются в:

```text
artifacts/models/runs/
```

## Где смотреть отчеты в ноутбуке

- `Run pipeline` — главное место: короткая таблица итогового прогноза.
- `Validate data` — отчет по качеству входных данных.
- `Model quality` — метрики моделей на walk-forward fold-ах.
- `Model selection` — финальное сравнение кандидатов и строка `selected = True`.
- `Selected model card` — карточка выбранной модели и причина выбора.
- `Forecast for date` — полная таблица прогноза со всеми техническими полями.
- `Drift and retraining decision` — drift-флаги и рекомендация по дообучению.
- `Logs` — последние строки лога прогнозов.
- `Final feature list` — список признаков финальной модели.

## Артефакты

После запуска пайплайн сохраняет результаты в папку `artifacts`.

Актуальная production-модель:

```text
artifacts/models/latest/
```

Внутри лежат:

- `model.pkl` — сериализованная модель;
- `feature_cols.json` — список признаков и порядок колонок;
- `model_config.json` — тип модели, дата обучения, период train;
- `preprocessing_config.json` — параметры подготовки данных;
- `outlier_thresholds.json` — пороги выбросов;
- `training_report.csv` — отчет по моделям;
- `validation_predictions.csv` — прогнозы на validation fold-ах;
- `model_card.md` — короткое описание модели.

История запусков:

```text
artifacts/models/runs/
```

Лог прогнозов:

```text
artifacts/forecasts/forecast_log.csv
```

Лог мониторинга drift:

```text
artifacts/monitoring/drift_log.csv
```

## Запуск без ноутбука

Пайплайн можно запустить из Python:

```python
from balance_pipeline import PipelineConfig, run_pipeline

config = PipelineConfig(forecast_date="2021-03-31")
results = run_pipeline(config)

forecast_result = results["forecast_result"]
print(forecast_result)
```

Для прогноза на следующий рабочий день после последнего факта:

```python
config = PipelineConfig(forecast_date=None)
results = run_pipeline(config)
```

## Важные правила пайплайна

- Для обучения используются только строки с `Date < FORECAST_DATE`.
- Если `FORECAST_DATE` уже есть в данных, ее `Balance`, `Income`, `Outcome` не используются при построении признаков прогноза.
- Факт за `FORECAST_DATE` используется только после прогноза для расчета качества.
- Validation/test не очищаются от выбросов.
- Outlier-пороги считаются только на обучающей истории.
- Если подходящего чекпоинта нет, пайплайн автоматически обучает модель заново.
